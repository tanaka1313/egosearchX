# 画面仕様書：エゴサ支援Webアプリ（Hololive EgoSearch）

関連文書：`docs/requirements.md`（要件定義書）。機能番号 F1〜F12 は要件定義書（2026-11-18 改訂）に対応する。旧番号は要件定義書の付録Bを参照。
「要調査」は要件定義書8章の確認が終わるまで確定しない項目。
画面イメージは `/mock`（破棄予定のモック）で確認できる。**モックが正**で、この文書はモックに合わせる（2026-11-18 に照合。食い違いを見つけたらモックに合わせて直す）。**スマホを基準に設計し、PC は6.2で定める。**
**用語**：検索先は「X」と「Yahoo!リアルタイム検索」。画面の文言では正式名を使い、短く「Yahoo」と書いてよいのはボタン（［Yahoo で開く］）、［⋯］のメニュー項目（「リンクをコピー（Yahoo）」）、お気に入り・いつものエゴサの行の検索先バッジ（「X」「Yahoo」「X＋Yahoo」。ただの識別子）だけ。

## 2. 共通要素

### 2.1 ヘッダー
- 左から順に、［≡］（メニューを開く）、**サイト名＝［興味の対象▾］＋「EgoSearch」**（「Hololive EgoSearch」の「Hololive」の部分が切替部品。既定は［ホロライブ▾］。押すと［ホロライブ］［にじさんじ］［その他］のメニューが開き、選ぶと閉じる（対象は今後増える前提。定義1か所に足すだけで並ぶ）。選択中は✓と太字。幅は一番長い名前に固定し、切り替えても動かない。Esc で閉じてボタンへフォーカスを戻す。**選ぶと条件ボタンの並びが、その対象のものに切り替わる**（条件ボタンは興味の対象ごとに別の並び。お気に入り・いつものエゴサ・履歴・削除済みは共通）。選択は端末内（localStorage）にだけ保存する。毎回いつでも選べ、初回カードは作らない）、**機能タイトル**（「X（Twitter）」。今後 YouTube 検索・TikTok 検索の同様のツールを同じサイトに足す予定なので、どの機能の画面かを示す。予定のみで Issue は作らない）。コマンドパレットのボタンは置かない（Ctrl/⌘+K とメニューの項目から開く）。
- **「いつものエゴサ」の帯**：ヘッダーのすぐ下に、**どのページでも（ランチャー S9 を含む）**固定で置く。いつものエゴサの先頭2件を並べる。帯の高さはいつものエゴサが0件でも同じ。「いつものエゴサ」の文字の横に**［＋］**（追加。S4-E の追加ページへ移動する）を置く。
- いつものエゴサのボタンは `▶ 配信後エ…(3)` の形にする。名前は幅に収まらない分を「…」で省略し、件数は常に表示する。今日実行済みのものには✓を付ける（色だけで示さない。✓の枠は常に確保し、押しても幅が変わらない）。省略しない名前は `title` と `aria-label` に入れる。表示件数は定数 `LIMITS.headerGroups`（2）。
- 3件目以降を実行したいときは、いつものエゴサのページ（S4）から実行する。S4 へのリンク「一覧」は、幅に余裕があるとき（sm 以上）だけ出す。余裕が無いときは出さない（メニューから行ける）。
- いつものエゴサが0件のときは、ボタンの代わりに「まだありません」を出す（［＋］は常にある）。
- いつものエゴサを実行してタブをブロックされたときは、ヘッダーのすぐ下に1行のインライン表示（`role="status"`、モーダルにしない）で、開けた数と許可の手順を案内する。個別リンクは S4 の一覧にある。
- ヘッダーは画面上部に通常配置する。他の要素の下に潜らない。
- 1280px 以上は左メニューが常時表示のため［≡］を出さない。
- ランチャー（S9）でも「いつものエゴサ」の帯を出す（帯自体がランチャーの入口のため）。フッターだけ、画面に集中させるため出さない。

### 2.1.1 フッター
- 画面の下に固定し、**最後の履歴を1件だけ**表示する：「前回 昨日 22:30 ぺこら…　［再実行］［履歴 →］」。履歴が無いときは「実行するとここに残ります」。
- ［履歴 →］は履歴のページ（S5）へ移動する。履歴の一覧はホームに置かない。
- トーストはフッターの上に出す（重ならない）。本文の下には、フッターの高さぶんの余白を取る。

### 2.2 左メニュー
- ［≡］で開く。**画面幅の約70%**（PC は最大 360px）。残りの約30%は半透明の幕で、**押すと閉じる**。全画面は覆わない。
- ヘッダーや他の要素と重ならない（メニューが最前面）。
- 上に閉じるボタン［×］。項目は**縦に並べる**：ホーム／条件ボタン／お気に入り／いつものエゴサ／履歴／削除済み（件数バッジ）／URL解析／このサイトについて／コマンドパレット。**メニューから、すべての機能と編集に行ける**ようにする。現在のページには印と文言（「表示中」）を付ける。**管理ページ（条件ボタン／お気に入り／いつものエゴサ）には、項目名の右に歯車のアイコン**を付け、追加・編集・削除をする場所だと示す（項目名だけでは、初めての人に意図が伝わらないため）。「管理」の文言は足さない（英語で長くなるため）。読み上げは「〇〇の管理」。
- 項目を押すとそのページへ移動して閉じる。Esc で閉じ、フォーカスを［≡］に戻す。開いたときは［×］にフォーカスする。

### 2.3 コンポーネント
| 名前 | 内容 |
|---|---|
| ChipButton（条件ボタン） | **ホームでは押して ON/OFF を切り替えるだけ**（編集・コピー・削除・並べ替え・表示の切替の部品は置かない）。先頭に固定サイズのアイコン枠を置き、ON は青の枠＋薄い青の塗り＋✓、OFF は灰色の枠＋○（薄い文字）。色だけに頼らず、アイコンの形でも区別する。**主ボタン（［X で開く］の塗りつぶしの青）とは見た目を分け、ON の状態と取り違えない**。**押しても幅・高さが変わらない**（アイコン枠・枠線の太さ・文字の太さを ON/OFF で揃える。見た目は1か所の定数に集める）。「新」バッジはボタンに重ねて置き、幅に含めない。リスト条件にはリストの印。**値付きの条件（数値・日付）を持つボタン**は［✓ ファボ [50] 件以上］のように、外枠の中に「切替ボタン（アイコン枠＋ラベル）＋入力欄＋接尾語」を並べる（`<button>` の中に入力欄は置けないため、外枠は `role="group"`）。切替ボタンと接尾語を押すと ON/OFF、入力欄で値を変えると自動で ON になり、値はボタンに保存する。入力欄は固定幅（数値は4桁が入る幅、日付は YYYY-MM-DD とカレンダーのアイコンが入る幅）で、値は入力欄の中で中央寄せにする。数値の入力欄には標準の上下ボタンを出さない（固定幅を食って値が見切れるため。値は直接入力する）。［期間］を指定中は、日付のボタンを無効の表示（⊘、薄い表示、入力不可。理由は `title` と読み上げ）にする（要件 F6） |

| EngineBadge | お気に入り（S3）の行では**短縮名**「X」「Yahoo」「X＋Yahoo」（ただの識別子なので短く。正式名は title と読み上げに出す。折り返さない）。名前が長いときは名前を「…」で省略し、バッジとボタンは縮めない。Yahoo!リアルタイム検索で使えない演算子があるときは、カードに警告アイコンを付ける（ホームの［Yahoo で開く］には印を付けない） |

## 3. S1：ホーム（`/`）

目的：検索語を入れ、条件ボタンを押し、開く。**直感操作だけで済む画面にする。** 日課の実行はヘッダー下の帯（全ページ）、前回の確認はフッターに任せ、ホームには検索の組み立てを置き、お気に入りは下に閉じた1行で置く（開閉は localStorage に記憶、初回は閉じる）。**表示と編集は分ける**：ホームの部品は押すだけで、追加・編集・削除・並べ替えはメニューの専用ページで行う。

### 3.2 要素と動作
- **いつものエゴサ**：ホーム本体には置かず、**ヘッダー下の帯に固定**する（2.1。ランチャーを含む全ページ）。どのページからでも1タップで実行できる。押すと、クリックを起点に `window.open` で全タブを開き、履歴に記録する。
- **検索語**：入力すると、下のクエリ表示がすぐ更新される。［完全一致］（チェックボックス）で引用符の有無を切り替える。
- **条件ボタン**：タップで ON/OFF を切り替えるだけ。見た目は 2.3 の ChipButton のとおり、**押しても幅・高さが変わらない**。
  - **折りたたみ**：「表示」にした条件ボタンのうち、**先頭8個**（定数 `LIMITS.foldChips`）を出す。隠れたボタンかサジェストがあるときは末尾に［もっと開く（+N）］を出し、押すと全件と**サジェスト検索条件**（最大20件、破線枠のボタン。押すとこの検索にだけ ON/OFF。見出しは「サジェスト（直近の検索などから・この検索にだけ足せます）」。条件ボタンの並びと詰まって見えないよう、上に余白を取る）を表示する。**N は開くと出てくるもの全部（隠れたボタン数＋サジェストの件数）**。ボタンが8個以下でも、サジェストがあれば［もっと開く］を出す（サジェストに届く道を無くさない）。**開いた後の［閉じる］は置かない**。隠れているボタンは描画しないのでフォーカスも当たらない。「表示」を外したボタン（S2）は、ホームの並び・件数・クエリのどれにも入れない。
  - **編集は別ページ**：ボタンの並びの最後の行の右端（行に余裕があるとき。無ければ次の行の右端）の「ボタンを編集 →」で、条件ボタンのページ（S2）へ移動する。作成・編集・コピー・削除・並べ替え・表示の切替は S2 だけで行う。ホームには［＋］、［×］、ドラッグの取っ手、長押しの動作を置かない。
- **期間**：［昨日から］［3日前から］［1週間前から］［📅 日付］。押した状態をもう一度押すと解除（指定なし）。ボタンと日付は同時に使えない。［日付］を押すとその場に `[開始日] 〜 [終了日] [×]` の入力行が開く：開始日だけ＝「以降」、終了日だけ＝「以前」、両方＝範囲（終了日を含む。出力時は翌日へ変換）。開始日が終了日より後なら、インラインで⚠を出す。**詳細条件の「期間」と同じコントローラーで、同じ状態を共有する**（どちらで変えても同期する）。注記は2行分の高さを常に確保し、押しても下の要素が動かない。
- **クエリ表示**：1行固定（折り返さない）。長いときは横にスクロールでき、キーボードでもスクロールできる。横は［コピー］（警告は「条件」の枠の一番下）。
- **ボタン列**：［X で開く］は**一番大事な操作**なので、塗りつぶしの青で最も大きく、横に広げて置く（ON の条件ボタンとは別の見た目）。隣に［Yahoo で開く］（外枠）、［☆ 保存］、［⋯］（リンクのコピー）。完全一致は**チェックボックス＋ラベル**で「条件」の枠の見出し行の右に置く（ボタンに見えないようにする）。
- **お気に入り**：検索エリアとは区切り線で分け、閉じた1行「☆ お気に入り（件数）」で置く。開くと「押して実行」だけの一覧と「お気に入りを編集 →」を出す。初回は閉じ、開閉は localStorage に記憶して次回もその状態で表示する。
- **サイトの説明**：一番上に1〜2文（このサイトを作った理由：「SNS の検索は毎日するのに、検索コマンドを覚えておく場所がない。その負担を減らしたくて作りました。」）と「詳しく →」（S10）。機能の一覧は書かない。
- **初回カードは置かない**（5巡目で廃止）。興味の対象はヘッダー（2.1）でいつでも切り替える。名前・タグから「推しエゴサ」を自動で作る機能も無い（検索語を入れて［☆ 保存］し、帯の［＋］でまとめる）。外部から何も取得しない。
- **検索語の入力**：Enter で X で開く（日本語入力の確定の Enter では開かない）。
- **クエリ表示**：入力欄の直下。X として出力される検索文字列。1行固定（長いときは横スクロール）。高さは一定で、文字の上下の余白を同じにし、細いスクロールバー（4px）は下の余白に収めて文字に重ねない。横に［コピー］（2.3 QueryPreview）。
- **注意（警告）**：「条件」の枠の一番下に、小さく薄い文字で一覧にする（Yahoo!リアルタイム検索で使えない演算子、期間と日付ボタンの重なり、URL 長など。無いときは出さない）。Yahoo!リアルタイム検索を使わない人には関係しない警告もあるので、クエリの横には置かない。［Yahoo で開く］にも印は付けない（警告はこの欄だけ）。出入りで動くのは枠より下（お気に入りの1行）だけで、押したボタン・クエリ表示・開くボタンは動かない。
- **［X で開く］**：新しいタブで開き、履歴に記録する。詳細条件で使った条件は、次回以降のサジェスト検索条件の候補になる（条件ボタンへは自動追加しない）。
- **［Yahoo で開く］**：［X で開く］の隣に外枠のボタンで置く（青の塗りつぶしは X だけ）。Yahoo!リアルタイム検索でも検索できることが、一目で分かるようにする（ボタンなので短い名前にする。`title` は「Yahoo!リアルタイム検索で開く」）。
- **［☆ 保存］**：保存シート（下からのシート）を開く。名前を入れ、**検索先（X／Yahoo!リアルタイム検索／両方。初期値は X）を選んで**「お気に入りに保存」。検索先は、お気に入りの［▶ 実行］といつものエゴサの一括実行で開く先になる。同じシートで「いつものエゴサに追加：既存を選ぶ／新規作成」もできる。狭い幅ではアイコンだけにする。
- **［⋯］**：リンクのコピーの小さなメニュー。「リンクをコピー（X）」「リンクをコピー（Yahoo）」（クエリのコピーはクエリ表示の横の［コピー］）。Esc または外側の操作で閉じる。
- **「条件」の枠**：完全一致（チェックボックス）、条件ボタン、期間、詳細条件、注意（警告）は同じ領域なので、1つの枠で囲む。
- **詳細条件**：「条件」の枠の中の開閉エリア。**初期は閉じている**。開くと 3.3 の内容。**末尾に、ホームと同じ開くボタン群（クエリ表示・［X で開く］［Yahoo で開く］［☆ 保存］［⋯］）を置く**（同じ状態・同じ処理。別の機能は作らない）。
- **履歴**：ホームには置かない。フッター（2.1.1）に最後の1件を出し、一覧はメニューの履歴ページ（S5）で見る。

### 3.3 詳細条件（個別設定、開閉エリア）
その検索だけの条件。可能な限り細かく指定できる。内容は要件定義書 F3 のとおり。

- セクション（それぞれ折りたたみ可）：語／アカウント／フィルタ／期間／表示／条件ボタンの項目別の無効化／テキストで追加。
  - **語**：完全一致・通常・表記ゆれ展開（複数の語をORで結ぶ）・除外を、それぞれ複数追加できる。
  - **アカウント**：from／to／メンション／list と、それぞれの除外。
  - **フィルタ**：リプライ、RT、引用、画像、動画、リンク、認証済み、言語、`min_faves`／`min_retweets`／`min_replies`。それぞれ「指定なし／含む／除く」の3択。
  - **期間**：ホームと同じ期間コントローラー（昨日から／3日前から／1週間前から／日付）。出力されるトークンも注記に表示する。「終了日を含む」と表示し、出力時に翌日へ変換する。
  - **表示**：Xの「最新」タブ。検索先はここに置かない（開くときは［X で開く］［Yahoo で開く］、保存するときは保存シートで選ぶ）。
  - **共通の無効化**：ONの条件ボタンの中身を項目ごとにチェックボックスで並べ、外すとこの検索でだけ無効になる。
- **テキストで追加**：上の欄に無い条件を、検索文字列のまま足す入力欄（等幅）。解析できない演算子もそのまま URL に出力する（生トークン）。木構造を編集する［構造］タブは置かない（上の各欄と重複するため）。
- 設定は即時にクエリ表示とプレビューへ反映する。
- 「この検索をリセット」で個別設定を全部消す（元に戻せるので確認は出さず、トーストに［元に戻す］）。

### 3.4 状態
| 状態 | 表示 |
|---|---|
| 初回（データなし） | 条件ボタンに、興味の対象ごとのプリセット（要件定義書 13章）が入り、ヘッダーの興味の対象はホロライブ（ホームに出るのはホロライブの並び）。いつものエゴサの帯は「まとめて1タップで開けます」。お気に入り・履歴は空状態の案内 |

| 保存済みと条件ボタンの食い違い | 条件ボタンを直しても、保存済みのお気に入り・いつものエゴサは変わらない（検索文字列を持つため）。S2 の編集シートに注記を出す |
| 警告あり | 「条件」の枠の一番下に⚠＋文言（［Yahoo で開く］には印を付けない） |

## 4. メニューのページ（S2〜S7）

共通：ヘッダーに「ホームへ戻る」のパンくずを置く。一覧は空状態（案内と次の操作）を持つ。削除は削除済みへ移し、トーストに［元に戻す］。

### S2：条件ボタン（`/buttons`）
ホームの条件ボタンは押すだけにしたので、**作成・編集・削除・並べ替えはこのページだけ**で行う（表示と編集を分ける）。ホームの「ボタンを編集 →」とメニューから開く。
- 一覧は、ヘッダーで選んでいる興味の対象の並び（説明文に対象の名前を出す）。件数と上限（30）も対象ごとに数える。
- 一覧（ドラッグで並べ替え、キーボードでも移動可）。各行：ラベル、中身の要約（等幅）、［表示］（ホームに出す／隠す。隠しても削除はされず、ホームの並び・件数・クエリから外れる）、［編集］［コピー］［×］。現在の件数／上限（例：12/30）を表示する。
- 一覧の下に**サジェスト検索条件**（直近の検索などから。最大20件）を出す。各行：条件（等幅）、［＋ 条件ボタンに追加］。**表示順は変えられない**（取っ手を置かない）。上限のときは追加を無効にして理由を表示する。
- **［＋ 追加］**：M1 を開く。ボタンの作り方は2つ：①ラベルと中身を入力、②**リスト**：URL（`https://x.com/i/lists/<ID>`）またはIDを貼る。ID を取り出して確認を表示する（例：「リスト 1412278227767218179」）。数字以外は受け付けない。
- プリセット（既定リスト F1 のボタンを含む。要件定義書 13章）から作られたボタンには「プリセット」の印を付ける。編集・削除はできる。削除後に戻したいときは「削除済み」から復元するか、［プリセットを追加］（今の興味の対象のプリセットのうち、無いものだけを足す）で再登録する。
- ホームと同じ折りたたみ（先頭8個）は使わず、全件を一覧する（非表示のものには「非表示」の印）。［コピー］は、そのボタンの条件の文字列をクリップボードにコピーする（トーストで知らせる）。

#### M1：条件ボタンの編集（下からのシート。PC は右側のシート）
- **ラベル**：表示名（必須。20文字まで）。
- **中身**：ボタンの本体は検索文字列。編集するときだけ条件の一覧に分けて表示し、保存で文字列に戻す。1つのボタンに複数の条件を持てる（例：ネタバレ除外 → 語A、語B）。各条件は種類（語・除外・完全一致・アカウント・リスト・フィルタ・生・**数値・日付**）と値。数値・日付のときは演算子（ファボ数／RT数／リプ数、開始日（以降）／終了日（以前・含む））を選び、値は**初期値**（ホームのボタンの中で変えられる）になる。ラベルが空なら演算子の名前（例：ファボ数）を使う。数値は1以上の整数、日付は YYYY-MM-DD でなければ保存せず、理由を表示する。［＋条件を追加］、各条件の［×］、ドラッグで並べ替え。
- **プレビュー**：中身から生成される文字列（等幅）と、Yahoo!リアルタイム検索で使えない演算子の警告。
- ［保存］／［キャンセル］。「保存済みのお気に入り・いつものエゴサには反映されません」と注記する（それぞれが検索文字列を持っているため）。
- 空のラベル・空の中身は保存できず、理由をフィールドの下に表示する（モーダルにしない）。

### S3：お気に入り（`/favorites`）
- 一覧（ドラッグで並べ替え）。各行：名前（長いときは「…」で省略）、検索先（短縮名のバッジ）、クエリ、最終実行、［▶ 実行］（検索先で開く。両方なら2タブ）［編集］［複製］［×］。絞り込み入力欄。
- **［×］**：削除済みへ移してトーストに［元に戻す］。お気に入りといつものエゴサは、それぞれが検索文字列を持っているので、**削除してもいつものエゴサには影響しない**（確認のモーダルは出さない）。
- ［編集］：専用ページ S3-E へ移動する。
- 保存済みの検索なので、条件ボタンの削除・変更の影響は受けない。

#### S3-E：お気に入りの編集（`/favorites/edit?id=<id>`）
- 以前のテキスト欄のシートは廃止した。詳細条件まで使うので、いつものエゴサの追加（S4-E）と同じく専用ページにする。
- 開いたとき、保存している検索文字列を解析して、**ホームと同じ検索の組み立て**（検索語・完全一致・条件ボタンの ON・期間・詳細条件）に展開する。展開の規則は要件定義書 11.4。
  - 照合するのは、今の興味の対象の条件ボタンのうち「表示」のものだけ。
  - 当てはまらなかった条件は詳細条件の各欄、または「テキストで追加」に入れる。内容は欠かさない。
- 上から順に、次のものを置く。
  - 名前
  - 検索先（`EnginePicker`）
  - 保存している検索文字列（編集前。等幅）と、展開に使った興味の対象の名前
  - 関連するいつものエゴサ：「同じ検索文字列の項目が、いつものエゴサ（「配信後エゴサ」1件）にあります。保存すると一緒に更新されます」。無ければ無いと書く
  - 検索語の入力、クエリ表示、［X で開く］［Yahoo で開く］（外枠。保存せずに試す）、「条件」の枠。詳細条件の末尾にも同じ開くボタンを置く
- ［複製］［キャンセル］［保存］は、見出しの右とページの末尾の2か所に置く。この画面の主な操作は保存なので、青の塗りつぶしは［保存］だけにする。
- ［保存］で文字列に組み立て直し、同じお気に入りを上書きする。**編集前の文字列（正規化して比較）と一致する、いつものエゴサの項目も更新する**。トーストで「いつものエゴサの N 件の項目も更新しました」と知らせ、［元に戻す］でお気に入りといつものエゴサを両方戻す。
- ［複製］は新しいお気に入りとして保存する（いつものエゴサは更新しない）。［キャンセル］は遷移前の画面に戻る。

### S4：いつものエゴサ（`/groups`）
- 一覧。各いつものエゴサ：名前、中身の検索（名前・クエリ。並べ替え可）、［▶ 一括実行］、［ブックマークURLを発行（M2）］、［編集］、［×］。「今日は済／未」。中身は**検索文字列＋検索先の並び**（項目は名前を持たない。正規化した文字列が一致するお気に入りがあればその名前を、無ければ文字列を表示する）。お気に入りを編集すると、一致する項目も一緒に更新される（S3-E）。お気に入りを消しても項目は消えない。
- **追加・編集は専用ページ `/groups/edit`**（新規は `?id` なし、編集は `?id=<id>`）。［＋ 追加］・帯の［＋］・［編集］から移動する。詳細条件まで使うので幅が要り、シートにはしない。1カラム（ホームと同じ幅）で、上から「名前／中身の検索／①／②」。［保存］［キャンセル］は見出しの右とページの末尾の2か所に置く。保存したら S4 に戻る。**［キャンセル］は遷移前の画面に戻る**（帯の［＋］からなら元のページ。直前のアプリ内のページを端末内（sessionStorage）に記録して使う。記録が無い＝直接開いたときは S4。外部サイトへは戻らない）。**名前の入力は「いつものエゴサの名前」1つだけ**。中身の入れ方は2つ。①**お気に入りから追加**：一覧の［＋ 追加］で、そのお気に入りの検索文字列と検索先を項目として入れ、開く順を並べる。各項目には名前（一致するお気に入りの名前）、検索先の短縮バッジ、検索文字列を出す。②**条件を指定して新しく作る**：**ホームと同じ検索の組み立て**（検索語、クエリ表示、「条件」の枠＝完全一致・条件ボタン（［もっと開く］→サジェスト）・期間・詳細条件）を、このページの中だけの状態で使う（ホームの ON/OFF・期間は変わらない。値付きの条件の値はボタンに保存される）。初期状態は空で、ホームの状態はコピーしない。クエリ表示の下と詳細条件の末尾に、［X で開く］［Yahoo で開く］（ホームと同じ部品。保存せずに開いて結果を確かめる。履歴には残る）と、**検索先の選択（保存シートと同じ部品。初期値は X）**、［お気に入りに保存して追加］を置く（2か所は同じ状態）。この画面の主な操作は追加なので、青の塗りつぶしは［お気に入りに保存して追加］だけにし、［X で開く］［Yahoo で開く］は外枠にする。追加したら組み立ては空に戻る。お気に入りにも保存され、**お気に入りの名前は「<いつものエゴサ名>：<検索語または1つ目のボタン名>」を自動で付ける**（入力欄は出さない。あとから S3 で直せる）。ホームの検索から作るときは S1 の保存シートを使い、新しいいつものエゴサの名前の初期値はお気に入りの名前にする。
- 検索が0件のいつものエゴサは保存できない。
- 一括実行：クリック起点で全タブを開く。ブロック時は、開けた数／失敗数と、個別リンク一覧を表示する。
- 例：「配信後エゴサ（3個）」＝配信タグ、ファンアートタグ、切り抜きタグ。「今日のエゴサ」＝期間「昨日から」を使う。

### S5：履歴（`/history`）
- 新しい順の一覧。各行：日時、検索語、使った条件ボタン、検索先、実行元。［再実行］［☆ お気に入りに保存］（検索先は実行したときのものを引き継ぐ）だけ（条件ボタンにする操作は置かない。条件ボタンへはサジェストから追加する）。
- 件数（例：42/100）、［全件削除］（ConfirmDialog）。

### S6：削除済み（`/trash`）
- 種類のタブ：［すべて］［条件ボタン］［お気に入り］［いつものエゴサ］。各タブに件数（例：お気に入り 3/20）を出す。削除した新しい順。各行：種類のバッジ、名前、削除日時、［復元］［中身を見る］［完全に削除］。中身は、条件ボタン＝条件の文字列、お気に入り＝クエリ、いつものエゴサ＝含む検索（名前と検索文字列）。
- **種類ごとに20件**を超えると、その種類の古いものから自動で完全削除される。その旨を上部に常時表示する。
- 条件ボタン・お気に入り・いつものエゴサは互いに独立しているので、連動して消えるものはない。いつものエゴサだけ、お気に入りだけ、を別々に復元できる。
- ［完全に削除］・［この種類をすべて完全削除］・［すべて完全削除］は ConfirmDialog（M3）を挟む。復元は確認なし。
- 復元先が上限に達している場合は、［復元］を無効にして理由を表示する。条件ボタンの行には、削除したときの興味の対象の名前を出し、復元はその対象の並びへ戻す（上限もその対象で判定）。

### S10：このサイトについて（`/about`）
- 冒頭の節「**このサイトを作った理由**」：SNS の検索は毎日のことなのに、検索コマンドを覚えておく機能がなく、毎日いくつも検索するのに、その検索を保存してまとめて実行することもできなかった。その負担を減らしたくて作った。そこで、何度でも使える検索ボタン（条件ボタン）を用意し、毎日の調べ物のためにお気に入りといつものエゴサの機能を加えた。続けて、検索結果は表示せず URL を作って X（Twitter）／Yahoo!リアルタイム検索を開くだけであることを1文で書く。
- 使い方の3ステップ（入力 → 条件を押す → 開く）、できること（検索の組み立て／X と Yahoo!リアルタイム検索の両対応／条件ボタン／お気に入りといつものエゴサ／履歴・削除済み・URL解析）、データの扱い（ログイン・API を使わない、保存先は端末内だけ、履歴を勝手に読み取らない、**ホロライブ（カバー株式会社）とは関係のないファンメイドの非公式ツールである**こと）。
- 好みの選び直しの節・ボタンは置かない（興味の対象の切替はヘッダー）。

### S7：URL解析（`/import`）
- テキスト入力欄にXまたはYahoo!リアルタイム検索のURLを貼り付ける。
- 解析結果を、ツリー形式で即時プレビューする。解析できなかった部分は「生トークン」として表示する。
- 対応外のURL（`x.com/search` でも `q` が無い等）には、理由を入力欄の下に表示する。
- ［ホームで編集する］（お気に入りの編集 S3-E と同じ規則で、今の興味の対象の条件ボタンの ON・検索語・期間・詳細条件に展開してホームへ移動）／［新規お気に入りとして保存］（検索先は貼った URL の検索先）。既存のデータは上書きしない。

## 5. S9：ランチャー（`/launch#<データ>`）

### 5.1 目的
ブックマークから開いたとき、設定入りのいつものエゴサを一括で実行する（F8）。

### 5.2 レイアウトと動作
```
┌────────────────────────────────┐
│ いつものエゴサ：配信後エゴサ     │
│ 3件の検索を新しいタブで開きます   │
│                                │
│   [▶ すべて開く]               │
│                                │
│ 1. 配信タグ（X）        [開く] │
│ 2. ファンアート（X）    [開く] │
│ 3. 切り抜き（X）        [開く] │
│ [ホームで開く（新規として保存）] │
└────────────────────────────────┘
```
- ページを開いただけでは自動でタブを開かない。**［すべて開く］のクリックを起点にする**。
- 日付の相対指定は、［すべて開く］の押下時点の日時で計算する（URL には `since:yesterday` などの記号のまま入っている）。
- 各行の名前は、この端末のお気に入りと検索文字列（正規化）が一致すればその名前、無ければ検索文字列を出す（URL には名前を入れない。別の端末でも開けるように、項目は検索文字列＋検索先だけ）。
- 個別の［開く］は、一括で開けなかったときの代替手段として常に表示する。
- ［ホームで開く］は、取り込んだ内容を新規のお気に入り／いつものエゴサとして保存するか確認してから S1 へ移動する。勝手に上書き保存しない。

### 5.3 ポップアップがブロックされた場合
- 開けたタブ数と失敗数を表示する。
- 「ブラウザのポップアップを許可してから、もう一度［すべて開く］を押してください」と案内する。

## 6. ダイアログ

### M2：ブックマークURL発行（F8）
- いつものエゴサの名前、含む検索の一覧を表示する。
- 生成されたURLを表示し、［コピー］と「ブックマークに追加する手順」の案内を出す。
- URLの長さが警告水準を超えたときは、含めるお気に入りを減らすよう促す（警告水準は定数。要件定義書 F8）。警告はダイアログ内のインライン表示で、別のモーダルは出さない。

### M3：確認ダイアログ
- 完全削除、種類ごと・すべての完全削除、履歴の全件削除だけに使う。［キャンセル］と赤の実行ボタン。Esc で閉じる。

### 6.1 モーダルにしないもの
警告、保存、削除（削除済みへの移動）は、モーダルを使わない。削除はトースト（［元に戻す］付き）、警告はアイコンとインライン表示。

### 6.2 PC（768px以上）の配置
スマホの配置を基準に、広い画面では次のようにする。
- **ホーム**：スマホと同じ1カラム（タイル型にしない）。幅は最大 672px で中央に寄せる。条件ボタンの折りたたみは、スマホと同じ先頭8個。帯のいつものエゴサは、幅に余裕があるぶん名前を長く表示する。
- **左メニュー**：768px〜1279px はスマホと同じ開閉（最大 360px）。1280px 以上は常時表示のサイドバー。
- **メニューのページ**：一覧は2カラム（一覧＋編集シート）。M1 は右側のシート。
- **コマンドパレット**：中央に表示。幅は最大 480px。
- キーボードショートカット：Ctrl/⌘+K でパレット、Esc で閉じる。

## 7. アクセシビリティ・表示方針
- すべての操作をキーボードで行えるようにする（メニューは Tab／Esc、並べ替えは Space＋矢印、ダイアログは Esc で閉じる）。
- 色だけで状態を示さない（条件ボタンは ON が ✓＋塗りつぶし、OFF が ○＋枠線で、`aria-pressed` も付ける。警告はアイコンと文言を併用）。
- **UIの文言は日本語と英語の両方に対応する（MVP の必須要件）。** 初期値はブラウザの言語（日本語以外は英語）、メニューの下部の言語切替で切り替えられる（設定画面は置かない）。文言は画面のコードに直書きせず、言語ごとの辞書から出す。長さが変わっても崩れないよう、帯の名前の省略、条件ボタンの幅固定、フッターの1行表示を、どちらの言語でも確かめる。クエリ文字列は等幅フォントで表示する。実装は GitHub の Issue で管理する。モックは日本語のみ。
- 最小対応幅は 360px。768px 未満は1カラム。
- 折りたたみで隠した要素は、フォーカスが当たらないようにする（`inert`）。
- 件数の上限値は画面の文言に直書きせず、定数から出す。
- **入力欄はページの背景より少し明るい面（トークン `--field`）と、はっきりした枠（`--input`）にする**。入力できる場所だと一目で分かるようにするため。色はトークン1か所で決め、入力欄ごとに背景色を指定しない。「条件」の枠は、ページの背景より少しだけ明るく、入力欄よりは暗くする。
- **スクロールバーは細く（6px）、半透明のつまみだけにする**。1行固定の横スクロール（クエリ表示）は、文字の行の下にスクロールバーの帯を取り、バーが文字に重ならないようにする（高さは文字の長さによらず同じ）。

## 8. 画面遷移
- ホーム ⇄ 各メニューのページ：左メニュー（［≡］またはサイドバー）で移動する。コマンドパレットからも移動できる。
- いつものエゴサの帯の［＋］（どのページでも）・S4 の［＋ 追加］［編集］→ S4-E（追加・編集ページ）→［保存］で S4 へ戻る。
- ホーム →「ボタンを編集 →」→ S2（条件ボタン。M1 のシートはここで開く）。ホーム →「お気に入りを編集 →」→ S3。いつものエゴサの帯のボタン→実行（画面は移動しない）、フッターの［履歴 →］→ S5。
- S4 → M2（発行）：ダイアログで開く。
- ブックマーク → S9 →（［ホームで開く］）→ S1。
- 履歴／お気に入り → ［再実行／実行］→ 新しいタブ（画面は移動しない）。
