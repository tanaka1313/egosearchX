# 画面仕様書：エゴサ支援Webアプリ（Hololive EgoSearch）

## 0. 前提
- 関連文書：`docs/requirements.md`（要件定義書。機能 F1〜F12、データ構造 11章）。データの規則（検索文字列が本体、文字列からの展開、連動、上限）は要件定義書に書き、この文書では参照だけにする。
- **モック（`/mock`）が正。** この文書はモックに合わせる（2026-11-18 に全面照合）。食い違いを見つけたらモックに合わせて直す。ただし、モックがダミーで再現できない振る舞い（タブを開く・ブロック時、URL の生成と長さ、解析、ランチャーの読み込み）はこの文書が正。
- モックにだけあるもの（上部のバナー、「データなしの状態で見る」、ランチャーの「ブロックされた状態を試す」、「（ダミー）」の文言）は本実装に入れない。
- **スマホを基準に設計する。** PC の配置は7章。
- **用語**：検索先は「X」と「Yahoo!リアルタイム検索」。画面の文言では正式名を使う。「Yahoo」と短くしてよいのは、［Yahoo で開く］、［⋯］の項目（「リンクをコピー（Yahoo）」）、行の検索先バッジ（「X」「Yahoo」「X＋Yahoo」）だけ。表示名は定数1か所から出す。複数の検索をまとめたものは「いつものエゴサ」と呼ぶ。

## 2. 共通の枠組み
すべての画面に、上から「ヘッダー → いつものエゴサの帯 → 本文」を置き、画面の下にフッターを固定する。ランチャー（S9）だけはフッターを出さない（画面に集中させるため）。帯はランチャーにも出す。

### 2.1 ヘッダー
- 左から［≡］（メニューを開く。1280px 以上はサイドバーが常にあるので出さない）、**サイト名＝［興味の対象▾］＋「EgoSearch」**、機能タイトル「X（Twitter）」の枠。
  - 機能タイトルは、YouTube／TikTok 版を同じサイトに足す予定があるため、どの機能の画面かを示す（予定のみ）。
  - 「EgoSearch」はホームへのリンク。
- **［興味の対象▾］**（既定はホロライブ）。
  - 押すとメニューが開き、［ホロライブ］［にじさんじ］［その他］が並ぶ。選択中のものには✓が付き、太字になる。対象は定義1か所に足すだけで並ぶ。
  - メニューの下には説明文を置く：「条件ボタンを、選んだ対象のものに切り替えます（お気に入り・いつものエゴサは共通）。この端末にだけ保存します。」
  - 選ぶと閉じる。外側を押しても閉じる。Esc で閉じると、ボタンにフォーカスが戻る。開いたときは、選択中の項目にフォーカスする。
  - ボタンの幅は一番長い名前に合わせて固定し、切り替えても動かない。
  - 切り替わるのは条件ボタンの並びだけ。選んだ対象は localStorage に保存する。初回カードは作らない。
- コマンドパレットのボタンは置かない（Ctrl/⌘+K かメニューから開く）。
- ヘッダーは通常の位置に置き、`sticky` にしない。

### 2.2 いつものエゴサの帯
- 高さは固定する（0件のときも同じ）。並びは「いつものエゴサ」の文字、［＋］、ボタン、［一覧］の順。
  - ［＋］は S4-E の追加ページへ移動する。
  - ボタンは先頭の `LIMITS.headerGroups`（2）件だけ並べる。
  - ［一覧］は S4 へのリンク。幅に余裕がある（sm 以上）ときだけ出す。
- ボタンは `▶ 配信後エ…(3)✓` の形。
  - 名前は「…」で省略する（PC では長めに出す）。件数は常に出す。
  - 今日実行したものには✓を付ける。✓の場所は常に確保し、押しても幅が変わらないようにする。
  - 省略しない名前と状態は `title` と `aria-label` に入れる。
- 押すと、そのいつものエゴサを一括実行する（クリックを起点に全タブを開き、履歴に残す）。画面は移動しない。
- 0件のときは、ボタンの代わりに「まとめて1タップで開けます」と出す（`title` に「保存した検索を、1タップでまとめて開けます（［＋］で作成）」）。
- 3件目以降は S4 から実行する。

### 2.3 フッター
- 画面の下に固定し、2行にする。
  - 1行目は**最後の履歴1件**：「前回 <日時> <検索語（無ければ検索文字列）>［再実行］ 履歴 →」。履歴が無いときは「実行するとここに残ります」。［履歴 →］は S5 へ移動する。
  - 2行目は**非公式の表記**：「ファンが作った非公式のツールです」（小さい文字）。
- 本文の下にはフッターの高さぶんの余白を取る。

### 2.4 左メニュー
- ［≡］で開く。幅は画面の約70%（最大 360px）。残りは半透明の幕で、押すと閉じる。メニューは最前面に出す。
- 上にサイト名と［×］。開くと［×］にフォーカスする。Esc か［×］で閉じると、フォーカスは［≡］に戻る。項目を押すと、そのページへ移動して閉じる。
- 項目は縦に並べる：ホーム／条件ボタン／お気に入り／いつものエゴサ／履歴／削除済み／URL解析／このサイトについて／コマンドパレット（`Ctrl/⌘+K` の表示）／バージョン情報／言語。
  - 現在のページには太字と「表示中」の文言を付け、`aria-current="page"` を付ける。
  - **管理ページ**（条件ボタン・お気に入り・いつものエゴサ）には、項目名の右に歯車のアイコンを付ける。読み上げは「〇〇の管理」。「管理」の文言は足さない。
  - 削除済みには件数のバッジを付ける（0件のときは出さない）。
  - バージョン情報はダイアログで開く（`VersionDialog`）。
  - **言語**：［日本語］［English］の2択（ON/OFF の見た目、`aria-pressed`）。初期値はブラウザの言語（日本語以外は英語）。設定画面は置かない。
- 1280px 以上は常にサイドバーとして出す（同じ項目）。

### 2.5 トースト
- 保存・コピー・エラー・削除を知らせる。削除と、元に戻せる変更には［元に戻す］を付ける。
- フッターの上に出し、フッターと重ねない。
- 警告はトーストで出さない（3.8）。

### 2.6 コマンドパレット
- Ctrl/⌘+K か、メニューの項目で開く。画面の中央に出す（最大幅 448px）。
- 並び：「▶ いつものエゴサ：<名前>（N個）」→「▶ お気に入り：<名前>」→「→ <ページ>へ移動」。入力した文字を含むものだけに絞る。
- Enter で先頭を実行し、Esc か外側で閉じる。開くと入力欄にフォーカスする。

## 3. 共通部品
ホーム（S1）、お気に入りの編集（S3-E）、いつものエゴサの追加②（S4-E）は、同じ部品で検索を組み立てる。

### 3.1 検索の組み立て（SearchScope）
- 部品は、検索語・完全一致・条件ボタンの ON・サジェストの ON・期間・詳細条件を、画面ごとの状態から読む。
  - ホームの状態は、ホームだけで使う。
  - S3-E・S4-E では、ページの中だけの状態を使う。ホームの ON/OFF や期間は変わらない。
  - 例外として、値付きの条件の値はボタン自体に保存されるので、どの画面で変えても共通になる。
- 条件ボタンの一覧・サジェストの候補は、どの画面でも同じもの（今の興味の対象の並び）を使う。
- 組み立てた文字列の規則（共通と個別の合成、項目の無効化、期間の出力）は要件定義書 F2・F3・F5。

### 3.2 条件ボタン（ChipButton）
- 押すと ON/OFF が切り替わるだけ。編集・コピー・削除・並べ替え・表示の切替は S2 で行う。
- 先頭に固定サイズのアイコン枠を置く。
  - ON：青の枠＋薄い青の塗り＋✓
  - OFF：灰色の枠＋○＋薄い文字
  - `aria-pressed` を付ける。
  - 主ボタン（［X で開く］の塗りつぶしの青）とは見た目を分ける。
- **押しても幅・高さが変わらない**（アイコン枠・枠線の太さ・文字の太さを ON/OFF で揃える）。見た目は1か所の定数（`toggleClass`）にまとめる。
- `title` にボタンの中身（検索文字列）を出す。種類のアイコンや条件の数は、ボタンに出さない。
- 「新」バッジ：サジェストから追加したボタンに付く。ボタンの右上に重ねて置き、幅には含めない。初めて押すと消える。
- **値付きの条件**（数値・日付）を持つボタンは［✓ ファボ [50] 件以上］のような形にする。
  - 外枠は `role="group"`（`<button>` の中に入力欄は置けないため）。中に「切替ボタン（アイコン枠＋ラベル）＋入力欄＋接尾語」を並べる。
  - 切替ボタンと接尾語を押すと ON/OFF が切り替わる。
  - 入力欄で値を変えると、値をボタンに保存し、その検索では ON にする。
  - 入力欄の幅は固定する。数値は4桁、日付は YYYY-MM-DD とカレンダーのアイコンが入る幅。値は中央に寄せる。数値の上下ボタンは出さない。高さはふつうのボタンと同じ。
  - 期間（3.4）を指定している間は、日付の条件を持つボタンを無効にする：⊘のアイコン、薄い表示、入力不可。`title` と読み上げで「期間を指定中のため無効です（期間を優先します）」と伝える。ON/OFF の状態は残す。

### 3.3 条件ボタンの並びと［もっと開く］
- 「表示」にしたボタン（S2）のうち、先頭の `LIMITS.foldChips`（8）個を並べる。「表示」を外したボタンは、並び・件数・クエリのどれにも入れない。
- 隠れたボタンかサジェストがあるときは、末尾に［もっと開く（+N）］を置く。N は開くと出てくるものの数（隠れたボタン＋サジェスト）。ボタンが8個以下でも、サジェストがあれば出す。
  - 押すと全部のボタンと、**サジェスト**の欄を出す。サジェストの欄は上に余白を取る。
  - 開いた後の［閉じる］は置かない。
  - 隠れているボタンは描画しない（フォーカスも当たらない）。
- サジェストの欄：見出しは「サジェスト（直近の検索などから・この検索にだけ足せます）」。
  - 候補はボタンと同じ大きさで、破線の枠にする。押すと、その検索にだけ ON/OFF する。
  - 候補が無いときは「検索するとここに候補が出ます」。
  - 候補の作り方（最大 `LIMITS.suggest` 件）は要件定義書 F6。
- 並びの最後の行の右端（余裕が無ければ次の行の右端）に「ボタンを編集 →」を置く（S2 へ移動する）。

### 3.4 期間（PeriodPicker）
- 「期間」の文字＋1つの枠の中に［昨日から］［3日前から］［1週間前から］［📅 日付］を並べる（狭い幅では枠の中で折り返す）。
  - 押した状態のものをもう一度押すと、解除になる（指定なし）。
  - 4つの中から1つだけ選べる。
  - 押した状態は、条件ボタンと同じ印（青の枠＋✓）で示す。
- ［日付］を押すと、その場に入力行 `[開始日] 〜 [終了日] [×]` が開く。
  - 開始日だけなら「以降」、終了日だけなら「以前」、両方なら範囲（終了日を含む）。
  - ［×］で日付の指定を解除する。
- 下に注記を1行置く。注記の高さは常に確保し、注記が変わっても下の要素は動かない。
  - 例：「2026-11-01 〜 2026-11-11（終了日を含む）」
  - 開始日が終了日より後なら「⚠ 開始日が終了日より後です」。この状態では保存できない。
- ホームの期間と、詳細条件の「期間」は**同じ部品・同じ状態**にする（どちらで変えても同期する）。
  - 詳細条件では、注記に出力も出す。例：「出力：since:yesterday（開くときは since:2026-11-17）」。
- 出力の規則（相対期間は記号で保存する、`until:` は終了日をそのまま出す）は要件定義書 F2。

### 3.5 クエリ表示（QueryPreview）
- 組み立てた X 用の検索文字列（開くときの日付に展開したもの）を、等幅フォントで1行に出す。
  - 折り返さず、長いときは横にスクロールする（キーボードでも操作できる。`tabIndex` とラベルを付ける）。
  - 高さは一定にし、文字の上下の余白を同じにする。細いスクロールバーは下の余白に収め、文字には重ねない。
  - 空のときは「（検索語か条件ボタンを選んでください）」。
- 右に［コピー］（アイコン）。クエリをクリップボードにコピーし、トーストで知らせる。
  - クエリが空のときは押せない。ボタンの場所は常に確保する。

### 3.6 開くボタン（OpenButtons）
- ［X で開く］と［Yahoo で開く］。
  - ［Yahoo で開く］の `title` は「Yahoo!リアルタイム検索で開く」。
  - 新しいタブで開き、履歴に残す。
- その画面の一番大事な操作のときだけ、［X で開く］を塗りつぶしの青にし、横に広げる。それ以外の画面では両方とも外枠にする。
- ［Yahoo で開く］には、警告の印を付けない。

### 3.7 OpenBar（ホームの操作のかたまり）
- 上から、クエリ表示（3.5）と、ボタン列［X で開く］［Yahoo で開く］［☆ 保存］［⋯］を並べる。
  - ［☆ 保存］は、狭い幅ではアイコンだけにする。
- ホームでは、入力欄のすぐ下と、詳細条件の末尾の2か所に置く。2か所は同じ状態・同じ処理で、機能は1つ。
- **［⋯］**：小さなメニュー「リンクをコピー（X）」「リンクをコピー（Yahoo）」。
  - コピーしたらトーストで知らせる。
  - Esc か外側を押すと閉じる。Esc のときはボタンにフォーカスを戻す。
  - クエリのコピーは、クエリ表示の［コピー］で行う。
- **［☆ 保存］の保存シート**（3.12）：
  - 上から次の順に置く。
    - 「お気に入りの名前」（初期値は「<検索語> の検索」、検索語が無ければ「新しい検索」）
    - 保存する検索文字列（等幅）
    - 説明：「この検索文字列を保存します。「昨日から」などは since:yesterday のまま保存し、開くときの日付で計算します。条件ボタンを後から直しても、保存したものは変わりません。」
    - 検索先（3.10）
    - 「いつものエゴサに追加（まとめて実行できます）」：［追加しない］／［「<名前>」に追加］（いつものエゴサの数だけ）／［新しいいつものエゴサを作る］
  - 「新しいいつものエゴサを作る」を選ぶと、名前の入力欄が出る。初期値はお気に入りの名前で、触るまでは名前と同じになる。
  - ［キャンセル］［保存］。名前が空のとき、または期間の開始日が終了日より後のときは保存せず、理由をシートの中に出す。

### 3.8 「条件」の枠と警告欄
- 上から次の順に、1つの枠に入れる。
  1. 見出し「条件」と、その右の［☐ 完全一致］（チェックボックス＋ラベル。ボタンの見た目にしない）
  2. 条件ボタンの並び（3.3）
  3. 期間（3.4）
  4. 詳細条件（3.9）
  5. 警告欄
- 枠の背景は、ページより少しだけ明るく、入力欄よりは暗くする。
- **警告欄**：枠の一番下に、小さく薄い文字で「⚠ <文言>」を並べる（`role="note"`）。
  - 警告が無いときは出さない。
  - 出したり消したりして動くのは、枠より下だけ。押したボタン・クエリ表示・開くボタンは動かない。
  - 内容：Yahoo!リアルタイム検索で使えない演算子（変換の規則は F5）、期間を指定中で使われない日付ボタン、クエリが `LIMITS.urlWarn`（500）文字を超えたとき。
  - **警告はダイアログ・トースト・クエリの横・［Yahoo で開く］に出さない。** パネルを勝手に開かず、フォーカスも奪わない。

### 3.9 詳細条件（DetailPanel）
- 「条件」の枠の中の開閉エリア（初期は閉じる）。見出しは「詳細条件」で、個別に指定した条件があれば「個別 N」のバッジを付ける。
- 中は開閉できる節に分ける（「期間」だけは初期で開く）。
  - **語**：完全一致の語／通常の語／表記ゆれ展開（OR で結ぶ）／除外する語。それぞれ複数入れられる（入力して Enter か［＋ 追加］。付けた語は［×］で外す）。
  - **アカウント**：`from:`／`to:`／`@`（メンション）／`list:`（リストID）。続けて「除外」の `-from:`／`-to:`／`-@`。
    - 除外は X の実機で確認済み（公式の記載は無い）。リストの除外（`-list:`）は X で検索がエラーになるので置かない（`docs/research-phase0.md` 6章 E6）。
    - 除外は Yahoo!リアルタイム検索では効かないので、警告欄で知らせる。
  - **フィルタ**：リプライ・リポスト・引用・画像・動画・リンク・認証済みに、それぞれ［指定なし］［含む］［除く］の3択を付ける。言語は選択（指定なし／日本語／英語／インドネシア語）。`min_faves`・`min_retweets`・`min_replies` は数値欄。
  - **期間**：3.4 と同じ部品で、出力も表示する。
  - **表示**：［☐ X の「最新」タブで開く（f=live）］。検索先はここに置かない（開くときはボタン、保存するときは保存シートで選ぶ）。
  - **共通（ON の条件ボタン）の項目別の無効化（N個のボタン）**：ON のボタンごとに、中身のトークンをチェックボックスで並べる。外したトークンは、その検索でだけ使わない（「この検索では無効」と表示する）。ON のボタンが無いときは「ON の条件ボタンがありません」。
  - **テキストで追加**：上の欄に無い条件を、検索文字列のまま足す欄（等幅、複数行）。解析できない演算子も、そのまま URL に出力する。
- 節の後に、画面ごとの操作を置く（ホームは OpenBar、S3-E は開くボタン、S4-E は②の操作）。
- 末尾に［この検索の個別設定をリセット］を置く。
  - 詳細条件と期間を空に戻す。確認は出さず、トーストに［元に戻す］を付ける。
- 設定は、すぐにクエリ表示と警告に反映する。

### 3.10 検索先（EnginePicker）
- 見出しは「検索先（▶ 実行で開く先）」。［X］［Yahoo!リアルタイム検索］［両方］のラジオボタンで、初期値は X。
- お気に入りを作る・直すすべての画面（保存シート、S3-E、S4-E の②）で、この部品を使う。
- 保存した検索先は、お気に入りの［▶ 実行］と、いつものエゴサの一括実行で使う（両方なら2タブ）。

### 3.11 行の部品と検索先バッジ
- **お気に入りの行（FavoriteRow）**：
  - 1行目：名前（長いときは「…」で省略。全文は `title`）、検索先バッジ、警告があれば⚠（内容は `title`）。
  - 2行目：保存している検索文字列（等幅、1行で省略。`title` に開くときの文字列）。
  - 右に［▶ 実行］。
  - バッジ・⚠・ボタンは縮めない。
- **検索先バッジ**：短い名前「X」「Yahoo」「X＋Yahoo」で、折り返さない。正式名は `title` と読み上げに出す。
- **いつものエゴサの項目の名前**：項目は名前を持たない。正規化した文字列が一致するお気に入りがあれば、その名前を出す。無ければ文字列を出す（要件定義書 11.4）。

### 3.12 シート・確認ダイアログ・空状態
- **シート**：
  - スマホでは下から、768px 以上では右側から出す。外側を押すか、［×］か Esc で閉じる。
  - 見出しの右に［×］。
  - 入力の誤りは、モーダルにせずシートの中に出す。
- **確認ダイアログ（D3）**：元に戻せない操作（完全削除、種類ごと・すべての完全削除、履歴の全件削除）にだけ使う。
  - 見出しと本文（「元に戻せません。」など）、［キャンセル］（初期のフォーカス）と赤の実行ボタン。
  - Esc か外側で閉じる。
- **空状態**：破線の枠に、案内の文と次の操作を出す。
- **ページの見出し（PageHead）**：見出しと、右に操作を並べる。パンくずは置かない（ホームへは左メニューか「EgoSearch」から行く）。

## 4. S1：ホーム（`/`）
目的：検索語を入れ、条件ボタンを押し、開く。**押すだけで使える画面にする。** 追加・編集・削除・並べ替えはメニューのページで行う。日課の実行は帯（2.2）、前回の検索はフッター（2.3）を使う。

### 4.1 レイアウト（スマホ。PC も同じ1カラムで中央に寄せる）
```
┌────────────────────────────────┐
│ [≡] [ホロライブ▾] EgoSearch (X（Twitter）)│  ← ヘッダー
├────────────────────────────────┤
│ いつものエゴサ [＋] [▶配信後エ…(3)✓][▶今日…(5)] 一覧│  ← 帯
├────────────────────────────────┤
│ SNS の検索は毎日するのに…  詳しく → │  ← 作った理由（1〜2文）
│ ( 🔍 名前や #タグ を入力 )          │
│ ぺこら -filter:retweets list:… [📋]│  ← クエリ表示＋コピー
│ [  X で開く  ][Yahoo で開く][☆][⋯]│
│ ┌ 条件 ──────────── ☐ 完全一致 ┐ │
│ │ [✓RTを除く][✓ホロメンから] …    │ │  ← 先頭8個
│ │ [もっと開く（+6）]  ボタンを編集 →│ │
│ │ 期間 [昨日から|3日前から|1週間前から|日付]│ │
│ │ （注記1行）                       │ │
│ │ ▸ 詳細条件                        │ │
│ │ ⚠ filter: は Yahoo!リアルタイム検索では…│ │  ← 警告（あるときだけ）
│ └──────────────────────┘ │
│ ─────────────────────────────  │

├────────────────────────────────┤
│ 前回 昨日 22:30 ぺこら [再実行] 履歴 →│  ← フッター
│ ファンが作った非公式のツールです     │
└────────────────────────────────┘
```

### 4.2 要素と動作
- **作った理由**：一番上に「SNS の検索は毎日するのに、検索コマンドを覚えておく場所がない。その負担を減らしたくて作りました。」と「詳しく →」（S10）。機能の一覧は書かない。
- **検索語の入力**：大きめの丸い入力欄（虫眼鏡のアイコン付き）。placeholder は「名前や #タグ を入力（Enter で X で開く）」。
  - 入力するとクエリ表示がすぐ変わる。
  - Enter で X で開く。日本語入力を確定する Enter では開かない。
- **OpenBar**（3.7）：入力欄のすぐ下に置き、入力・クエリ・開くボタンを1かたまりにする。ホームでは［X で開く］が主ボタン。
- **「条件」の枠**（3.8）：詳細条件の末尾にも OpenBar を置く。
- **お気に入り**：区切り線の下に、閉じた1行「☆ お気に入り（件数）」を置く。
  - 開くと全件を並べ、末尾に「お気に入りを編集 →」（S3）を置く。各行は押して実行するだけの簡単な形にする：名前、開くときの検索文字列（等幅、1行で省略）、［▶ 実行］。検索先バッジと⚠は出さない（S3 の行で出す）。
  - 開閉は localStorage に記憶する。初回は閉じた状態にする。
  - 0件のときは「条件を触って気に入ったら ☆ 保存 でここに入ります」。
- 開いた検索で使った条件は、サジェストの候補になる（条件ボタンへは自動で足さない。F6）。
- 初回カード、名前やタグからの自動作成、外部からの取得は無い。

### 4.3 状態
| 状態 | 表示 |
|---|---|
| 初回（データなし） | 条件ボタンは興味の対象ごとのプリセット（要件定義書 13章）、興味の対象はホロライブ。帯は「まとめて1タップで開けます」、お気に入りは0件、フッターは「実行するとここに残ります」 |
| 警告あり | 「条件」の枠の一番下に⚠＋文言（3.8） |

## 5. メニューのページ
- 共通：本文は1カラム。上は見出し（PageHead）、次に説明文。
- 一覧には空状態（3.12）がある。
- 削除は削除済みへ移し、トーストに［元に戻す］を付ける（確認は出さない）。

### 5.1 S2：条件ボタン（`/buttons`）
- 見出しの右：件数／上限（例 `12/30`。`LIMITS.chips`、興味の対象ごとに数える）、［プリセットを追加］、［＋ 追加］（上限のときは押せない）。
- 説明文に、今選んでいる興味の対象の名前を出す（「いま選んでいる「ホロライブ」の並び。ヘッダーで切り替えると別の並びになります」）。上限のときは「⚠ 上限（30件）です。不要なボタンを削除してください。」。
- **一覧**は全件を並べる（折りたたまない）。ドラッグで並べ替えられる（取っ手。キーボードでは Space で持ち上げ、矢印で動かす）。
  - 各行の左：ラベル、印（「プリセット」「新」「非表示」）、条件の数（「N条件」）、中身の検索文字列（等幅、1行で省略）。
  - 各行の右：
    - ［☐ 表示］：ホームに出すかどうか。外してもボタンは消えず、ホームの並び・件数・クエリから外れる。
    - ［編集］：D1 を開く。
    - ［コピー］：条件の文字列をクリップボードにコピーし、トーストで知らせる。
    - ［×］：削除済みへ移す。
- ［プリセットを追加］：今の興味の対象のプリセットのうち、まだ無いものだけを足す（上限まで）。足した数をトーストで知らせる。すべてあるときは「プリセットのボタンはすべて登録済みです」。
- 0件のときは、空状態に［プリセット（<対象>）を追加］を置く。
- **サジェスト**（一覧の下）：見出しは「サジェスト（直近の検索などから）」。
  - 説明：「最大20件。気に入ったものを条件ボタンに追加できます。候補の表示順は変えられません。」
  - 各行（破線の枠）：検索文字列（等幅）と［＋ 条件ボタンに追加］。
  - 追加したボタンは、ラベルが文字列（長ければ省略）で、「新」の印が付く。
  - 上限のときは追加を押せず、「⚠ 条件ボタンが上限（30件）のため追加できません」と出す。

#### D1：条件ボタンの編集（シート）
- 見出しは「条件ボタンを追加」か「条件ボタンを編集」。
- **ラベル**（ボタンの表示名）。
- **中身**（複数の条件を持てる）。
  - ボタンの本体は検索文字列。編集の間だけ、条件の行に分けて表示し、保存で文字列に戻す（要件定義書 F6・11.3）。
  - 各行：取っ手（ドラッグで並べ替え）、種類、値、［×］。種類は語（通常）・語（完全一致）・除外・リスト・アカウント・フィルタ・生トークン・数値・日付。
  - 種類が数値か日付のときは、演算子も選ぶ。数値はファボ数／RT数／リプ数、日付は開始日（以降）／終了日（含む）。値は**初期値**になる（ホームのボタンの中で変えられる）。接尾語も表示する。
  - ［＋ 条件を追加］。
- **リストを登録**：URL（`https://x.com/i/lists/<ID>`）か数字の ID を貼って［取り出す］を押す。
  - 取り出せたら、リストの条件を足す。ラベルが空なら仮の名前（「リスト <ID の先頭>…」）を入れる。
  - 取り出せないときは「リストの URL（https://x.com/i/lists/…）または数字の ID を入力してください」。
- **プレビュー**：中身から作った文字列（等幅）。Yahoo!リアルタイム検索で使えない演算子（`list:`、`filter:`）があれば、注意を添える。
- 編集のときは「保存済みのお気に入り・いつものエゴサには反映されません（それぞれが検索文字列を持っているため）。」と注記する。
- ［キャンセル］［保存］。次の場合は保存せず、理由をシートの中に出す。
  - ラベルが空。ただし数値・日付の条件があれば、演算子の名前（例：ファボ数）をラベルにして保存する。
  - ラベルが20文字を超える。
  - 条件が1つも無い。
  - 数値が1以上の整数でない。日付が YYYY-MM-DD でない。
  - 上限を超える。

### 5.2 S3：お気に入り（`/favorites`）
- 説明文：
  - 検索文字列を持つので、条件ボタンを直しても変わらない。
  - ［編集］では条件ボタンと詳細条件に展開して直せる。
  - 編集すると、同じ文字列のいつものエゴサの項目も更新される。
  - 削除しても、いつものエゴサには影響しない。
- 「名前で絞り込み」の入力欄。
- **一覧**：取っ手（ドラッグで並べ替え）＋ FavoriteRow（3.11）＋［編集］（S3-E へ移動）＋［×］（削除済みへ移す）。
  - 絞り込み中は並べ替えを反映しない。その旨を「絞り込み中は並べ替えを反映しません」と出す。
- 0件のときは「ホームで条件を触って ☆ 保存 するとここに入ります」。

### 5.3 S3-E：お気に入りの編集（`/favorites/edit?id=<id>`）
- 開いたとき、保存している文字列を、今の興味の対象の条件ボタン（「表示」のものだけ）に当てはめて、検索の組み立て（3.1）に展開する。当てはまらなかった条件は、詳細条件の各欄か「テキストで追加」に入れる（内容は欠かさない。要件定義書 11.4）。
- 上から：
  1. 見出し「お気に入りを編集」と、右に［複製］［キャンセル］［保存］
  2. 名前
  3. 検索先（3.10）
  4. 「保存している検索文字列（編集前）」（等幅）と注記
     - 「「<対象>」の条件ボタンに当てはめて展開しました。当てはまらなかった条件は詳細条件に入っています。」
     - 関連するいつものエゴサ。あれば「同じ検索文字列の項目が、いつものエゴサ（「配信後エゴサ」1件）にあります。保存すると一緒に更新されます。」、無ければ「この検索文字列を持つ、いつものエゴサはありません。」
  5. 検索語の入力、クエリ表示、［X で開く］［Yahoo で開く］（どちらも外枠。保存せずに試す）
  6. 「条件」の枠（詳細条件の末尾にも、同じ開くボタン）
  7. 末尾に、見出しと同じ［複製］［キャンセル］［保存］
- この画面の主な操作は保存なので、青の塗りつぶしは［保存］だけにする。
- ［保存］：文字列に組み立て直して、このお気に入りを上書きする。
  - 編集前の文字列と一致する、いつものエゴサの項目も更新する（要件定義書 11.4）。
  - トーストで「いつものエゴサの N 件の項目も更新しました」と知らせ、［元に戻す］で両方を戻す。
- ［複製］：「<名前>（複製）」として新しいお気に入りに保存する（いつものエゴサは更新しない）。
- ［キャンセル］：遷移前の画面に戻る（9章）。
- 名前が空、検索が空、期間の開始日が終了日より後のときは保存せず、操作の横に理由を出す。
- id が見つからないときは、空状態「このお気に入りは見つかりません（削除済みの可能性があります）」と、一覧へのリンクを出す。

### 5.4 S4：いつものエゴサ（`/groups`）
- 見出しの右に［＋ 追加］（S4-E へ移動）。
- 説明文：
  - タイミング（配信後・毎朝など）ごとに、複数の検索を一括で開ける。
  - 先頭2件は帯に並ぶ。
  - 追加の方法は2つ。
  - 中身は検索文字列の並び。
  - お気に入りを編集すると連動するが、削除しても消えない。
- **一覧**：各行の上の段：名前（件数）、「✓ 今日は済」か「□ 今日は未」、［▶ 一括実行］［ブックマークURL］（D2）［編集］（S4-E）［×］。下の段：項目の名前（3.11）を「／」でつないだもの。
- 一覧では並べ替えない（項目の順は S4-E で変える）。
- **一括実行**：クリックを起点に、各項目をその検索先で開く。
  - ブロックされたときは、開けた数と失敗の数、個別のリンクの一覧をこのページの中に出す（モーダルにしない）。
- 0件のときは「いつものエゴサがありません。「配信後エゴサ」などを作ってみましょう」と［＋ 追加］。

#### D2：ブックマークURLの発行（シート）
- 見出しは「ブックマークURLを発行：<名前>」。
- 中身：項目の名前の一覧、生成した URL（等幅）、追加する手順（「URL をコピーして、ブックマークの URL 欄に貼り付けます」）。
- URL が警告水準（要件定義書 F8、定数）を超えたときは、シートの中に「お気に入りを減らすと短くなります」と出す。
- ［閉じる］［コピー］。コピーしたらトーストで知らせる。

### 5.5 S4-E：いつものエゴサの追加・編集（`/groups/edit`、編集は `?id=<id>`）
- 1カラムで、上から：
  1. 見出し（「いつものエゴサを追加」か「いつものエゴサを編集」）と［キャンセル］［保存］
  2. 名前（いつものエゴサの名前。名前の入力はこれ1つ）
  3. 中身
  4. ①
  5. ②
  6. 末尾の［キャンセル］［保存］
- **中身の検索**（「中身の検索（N個。順に開きます）」）：
  - 各項目に、番号＋名前（3.11）、検索先バッジ、検索文字列（等幅）、［↑］［↓］（並べ替え）、［×］（外す）を出す。
  - 0件のときは「まだありません。下の①か②で追加してください。」。
- **①お気に入りから追加**：お気に入りの名前と［＋ 追加］。押すと、その文字列と検索先を項目として末尾に足す。
- **②条件を指定して新しく作る**：検索の組み立て（3.1）を、このページの中だけの状態で使う（初期は空）。
  - 上から、検索語の入力とクエリ表示、自動で付く名前の表示、操作、「条件」の枠。詳細条件の末尾にも、同じ操作を置く。
  - 自動で付く名前の表示：「お気に入りにも保存されます。名前は自動で付きます：<名前>」。名前は「<いつものエゴサ名>：<検索語、無ければ1つ目の ON のボタン名>」。
  - 操作：
    - ［X で開く］［Yahoo で開く］（外枠。保存せずに試す。履歴には残る）
    - 検索先（3.10）
    - ［お気に入りに保存して追加］（横いっぱいの青。この画面の主な操作）
    - 2か所に置いた操作は、同じ状態を共有する。
  - ［お気に入りに保存して追加］を押すと、お気に入りとして保存し、項目にも足し、組み立てを空に戻す。
  - 検索が空のときと、期間の開始日が終了日より後のときは、追加しない。
- ［保存］：名前が空のときと、項目が0件のときは保存しない。保存したら S4 に戻る。［キャンセル］は遷移前の画面に戻る（9章）。
- id が見つからないときは、空状態と、一覧へのリンクを出す。
- ホームの検索からいつものエゴサを作るときは、保存シート（3.7）を使う。

### 5.6 S5：履歴（`/history`）
- 見出しの右：件数／上限（例 `42/100`）、［全件削除］（D3。0件のときは押せない）。
- 一覧は新しい順。各行に次を出す。
  - 日時、検索先（正式名のバッジ）、実行元（「ホーム」「いつものエゴサ「…」」など）
  - 検索文字列（等幅）
  - 「使った条件ボタン：…」（あるときだけ）
  - ［再実行］［☆ お気に入りに保存］（実行したときの検索先を引き継ぐ）
- 「条件ボタンにする」操作は置かない（サジェストから足す）。
- 全件削除の確認文：「元に戻せません。「今日は済」の表示にも影響します。」
- 0件のときは「実行するとここに残ります」。

### 5.7 S6：削除済み（`/trash`）
- 見出しの右：［すべて完全削除］（D3）。
- 上部に常に注記を出す：
  - 種類ごとに `LIMITS.trash`（20）件まで残り、超えると古いものから自動で完全に削除される。
  - 種類は互いに独立している。
- 種類のタブ：［すべて N］［条件ボタン N/20］［お気に入り N/20］［いつものエゴサ N/20］。種類のタブでは、右に［<種類>をすべて完全削除］（D3）を出す。
- 一覧は削除した新しい順。各行：
  - 種類のバッジ（条件ボタンには、削除したときの興味の対象の名前も出す）
  - 名前と「削除 <日時>」
  - ［復元］
  - ［中身を見る／中身を隠す］：開くと中身を出す。
    - 条件ボタン：条件の文字列
    - お気に入り：開くときのクエリ
    - いつものエゴサ：項目の名前と文字列
  - ［完全に削除］（D3）
- 復元は確認なしで行う。
  - 条件ボタンは、削除したときの興味の対象の並びに戻す。
  - 戻す先が上限のときは［復元］を押せず、「⚠ 条件ボタンが上限（30件）のため復元できません」と出す。
- 連動して消えるもの・戻るものは無い（要件定義書 F10）。
- 0件のときは「削除したものはここに入ります」（種類のタブでは「削除した<種類>はありません」）。

### 5.8 S7：URL解析（`/import`）
- 説明文：X か Yahoo!リアルタイム検索の URL を貼ると、条件に分ける。解析できない部分は生トークンとして残し、URL に戻したときに欠けない。既存のデータは上書きしない。
- 入力欄（複数行、等幅）に貼ると、すぐに結果を出す。
  - トークンを1行ずつ並べ、「条件」か「生トークン（解析できなかった部分）」かを添える。
  - 解析の規則は要件定義書 F4。
- 読めないときは、入力欄の下に理由を出す。
  - 「URL として読み取れません」
  - 「X または Yahoo!リアルタイム検索の URL ではありません」
  - 「検索語（q / p）が含まれていません」
- 操作：
  - ［ホームで編集する］：S3-E と同じ規則で、ホームの組み立てに展開してホームへ移動する。
  - ［新規お気に入りとして保存］：検索先は、貼った URL の検索先にする。
  - 読めないときは、どちらも押せない。

### 5.9 S10：このサイトについて（`/about`）
上から次の節を置く。
1. **このサイトを作った理由**
   - SNS の検索は毎日のことなのに、検索コマンドを覚えておく機能がない。
   - 毎日いくつも検索するのに、保存してまとめて実行することもできなかった。その負担を減らすために作った。
   - そこで、何度でも使える検索ボタン（条件ボタン）を用意し、お気に入りといつものエゴサを加えた。
   - 続けて、「**検索結果はこのサイトには表示しません。**」検索の URL を作って X（Twitter）や Yahoo!リアルタイム検索を開くだけ。
2. **使い方（3ステップ）**
   1. 名前やタグを入力する
   2. 条件ボタンと期間を押して絞り込む
   3. ［X で開く］か［Yahoo で開く］を押す
3. **できること**（カード5枚）
   - 検索を組み立てる
   - X と Yahoo!リアルタイム検索の両方で開く
   - 条件ボタンを自分用に育てる
   - 保存して、いつものエゴサでまとめて開く
   - 履歴・削除済み・URL解析
4. **データの扱い**
   - ログインしない。API を使わない。
   - 保存は端末のブラウザだけ。
   - 履歴や閲覧内容を勝手に読み取らない。
   - **ホロライブ（カバー株式会社）とは関係のない、ファンが作った非公式のツールである。**

興味の対象の選び直しはヘッダーで行うので、この画面には置かない。

## 6. S9：ランチャー（`/launch#<データ>`）
ブックマークから開き、いつものエゴサを一括で実行する（F8）。帯は出し、フッターは出さない。

```
┌────────────────────────────────┐
│ いつものエゴサ：配信後エゴサ     │
│ 3件の検索を新しいタブで開きます   │
│ [▶ すべて開く]                  │
│ 1. 配信タグ（X）          [開く] │
│    #配信タグA since:2026-11-17   │
│ 2. ファンアート（X）      [開く] │
│ 3. 切り抜き（X と Yahoo!リアルタイム検索の両方）[開く] │
│ [ホームへ]                       │
└────────────────────────────────┘
```
- ページを開いただけではタブを開かない。**［すべて開く］のクリックを起点に開く。**
- 相対期間は、押した時点の日付に展開する（URL には `since:yesterday` などの記号のまま入っている）。
- 各行：番号、名前（3.11。この端末のお気に入りと一致すればその名前。無ければ文字列）、検索先の正式名、開くときの検索文字列（等幅、1行で省略）、［開く］。
  - URL には名前を入れない（項目は検索文字列＋検索先だけ）。
- 個別の［開く］は、一括で開けなかったときの代わりとして常に出す。
- ［ホームへ］：ホームへ移動するだけ（何も保存しない）。
- **ポップアップがブロックされたとき**：［すべて開く］の下に表示する（`role="status"`、モーダルにしない）。
  - 「N個のタブを開き、M個は開けませんでした。」
  - 「ブラウザのポップアップを許可してから、もう一度［すべて開く］を押してください。下の個別リンクからも開けます。」

| エラー | 表示 |
|---|---|
| ハッシュが無い／壊れている | 空状態「ブックマークURLを読み込めませんでした」と［ホームへ］ |
| 知らないバージョン | 「新しい形式のURLです。アプリを更新してください」 |
| URL が長い | 発行のとき（D2）に警告済み。読み込めれば通常どおり |

スマホの配置を基準にして、広い画面では次のようにする。

## 8. アクセシビリティと表示方針
- **すべての操作をキーボードで行える。**
  - メニューは Tab と Esc。
  - 並べ替えは、取っ手を Space で持ち上げて矢印で動かす。S4-E は［↑］［↓］。
  - ダイアログとシートは Esc で閉じる。
  - 横スクロールのクエリ表示にもフォーカスが当たる。
- **色だけで状態を示さない。** ON は✓、OFF は○、無効は⊘で示し、`aria-pressed` を付ける。警告はアイコンと文言を一緒に出す。帯の今日済みは✓で示す。
- **ボタンを押しても画面がガタつかない。** ON/OFF・クエリの長さ・警告の有無で、押した部品・クエリ表示・開くボタンの大きさと位置を変えない。画面が動いてよいのは、開く・閉じる操作だけ。
- **モーダルにしないもの**：警告・保存・削除（削除済みへの移動）・入力の誤り。モーダルは D3 だけ。
- **UI の文言は日本語と英語の両方に対応する（MVP の必須）。**
  - 文言は辞書から出し、画面のコードに直書きしない。
  - 帯の名前の省略、条件ボタンの幅、フッターの1行表示が、どちらの言語でも崩れないことを確かめる。
  - 検索文字列は言語によらず同じで、等幅フォントで出す。
  - モックは日本語のみ。
- 最小幅は 360px。768px 未満は1カラム。
- 件数の上限値は文言に直書きせず、`lib/limits.ts` の定数から出す。
- **配色：ダークモード固定**（切替は作らない。`color-scheme: dark`）。
  - 主ボタンは塗りつぶしの青を1つだけにし、ON の状態（青の枠＋薄い塗り＋✓）とは別の見た目にする。
  - 入力欄は、ページより少し明るい面（トークン `--field`）と、はっきりした枠（`--input`）にする。明るさは「ページ < 「条件」の枠 < 入力欄」の順。
- **スクロールバー**は細く（6px）し、半透明のつまみだけにする。

## 9. 画面遷移
- ホーム ⇄ 各メニューのページ：左メニュー（［≡］かサイドバー）、またはコマンドパレットで移動する。「EgoSearch」でホームへ戻る。
- ホームから：
  - 「ボタンを編集 →」→ S2（D1 はここで開く）。
  - 「お気に入りを編集 →」→ S3。
  - 「詳しく →」→ S10。
- どのページからも：
  - フッターの［履歴 →］→ S5。
  - 帯のボタン → 実行（画面は移動しない）。
  - 帯の［＋］→ S4-E（追加）。
  - 帯の［一覧］→ S4。
- S3 の［編集］→ S3-E。S4 の［＋ 追加］［編集］→ S4-E。S4 → D2（シート）。
- S3-E・S4-E の［キャンセル］は**遷移前の画面に戻る**。
  - 直前に開いていたアプリ内のページを sessionStorage に記録して使う。
  - 記録が無い（直接開いた）ときは、S3-E は S3 に、S4-E は S4 に戻る。外部のサイトへは戻らない。
  - S4-E の［保存］は S4 に戻る。
- S7 の［ホームで編集する］→ S1。
- ブックマーク → S9 → ［ホームへ］→ S1。
- 履歴・お気に入り・パレットの実行は、新しいタブで開く（画面は移動しない）。
